1 «قالب الطلب الذكي» لإرسال وتحديد التعديلات البرمجية بدقة
📋 قالب إرسال الطلب (انسخه أو املأه عند طلب أي تعديل): يضمن التعديل الدقيق في ثوانٍ دون تداخل مع شاشات أخرى
1. الصفحة أو الرابط: (مثال: صفحة المنتجات /products أو نقطة البيع /sales/create أو الإعدادات /settings)
2. العنصر المطلوب: (مثال: زر الحذف في جدول الأصناف / إجمالي الفاتورة / شعار الترويسة / خيار الخصم)
3. الوضع الحالي: (ماذا يحدث الآن بالتحديد؟ مثال: الزر لا يستجيب، أو ينقلني لصفحة أخرى، أو الحساب غير دقيق، أو يظهر خطأ 500)
4. التعديل المطلوب: (ما هو الشكل أو السلوك الذي تريده بالضبط؟ مثال: إضافة زر طباعة، أو احتساب الخصم كنسبة مئوية، أو إضافة أيقونة)
💡 أمثلة عملية توضح كيفية استخدام القالب في مختلف أجزاء النظام:
🎨 مثال 1: تعديل واجهة وأزرار (UI)
الصفحة: نواقص المخزون (/inventory/low-stock)
العنصر: عمود "الإجراءات" في جدول النواقص.
الوضع الحالي: يوجد فقط زر "إيداع مخزني".
المطلوب: إضافة أيقونة عين (eye) تنقل مباشرة لصفحة تفاصيل الصنف (products.show).
⚙️ مثال 2: تعديل حسابات ومنطق (Logic)
الصفحة: إنشاء فاتورة شراء (/purchases/create)
العنصر: حقل الخصم وإجمالي الفاتورة الصافي.
الوضع الحالي: الخصم يُحسب كقيمة نقدية ثابتة فقط.
المطلوب: خيار لتطبيق الخصم كنسبة مئوية (%) أو قيمة (ج.م) مع تحديث الإجمالي تلقائياً.
🖨️ مثال 3: تعديل في مخرجات الطباعة
الصفحة: طباعة فاتورة المبيعات الحرارية 80 مم.
العنصر: ترويسة الفاتورة وتذييل الباركود.
الوضع الحالي: يظهر اسم الشركة دون رقم الهاتف.
المطلوب: إضافة رقم الهاتف من إعدادات الشركة تحت الاسم، وإخفاء الباركود إذا كانت ملغاة.
⚡ إرشادات سريعة لسرعة الإنجاز والوصول الفوري للمشكلة:
  • رابط المتصفح (URL): مجرد ذكرك للرابط (مثل /settings أو /shifts) يحدد ملف الـ View والـ Controller فوراً.
  • رسائل الخطأ: إذا ظهرت أي رسالة خطأ بالإنجليزية على الشاشة، انسخ أول سطرين منها فهما يحددان رقم السطر والسبب بدقة 100%.
  • تحديد النطاق (Scope): وضّح إن كان التعديل خاصاً بشاشة معينة فقط (مثال: "في جدول المنتجات فقط وليس العملاء").
2 خريطة طبقات النظام والملفات المسؤولة عنها (Architecture Mapping)
الطبقة (Layer) المسار في مجلد المشروع الوظيفة والمكونات التابعة
الروابط (Routes) routes/web.php توجيه روابط المتصفح والـ HTTP Verbs (GET, POST, PUT, DELETE) والميدلوير.
المتحكمات (Controllers) app/Http/Controllers/ استقبال الطلبات، التحقق من الحقول (validate)، والربط بين الـ Views والخدمات.
منطق الأعمال (Services) app/Services/ العمليات الدقيقة: InventoryService (حسابات FIFO)، PrintTemplateService.
قاعدة البيانات (Models) app/Models/ & database/migrations/ جداول البيانات، القيود والعلاقات (foreignKey, hasMany, belongsTo).
واجهات العرض (Blade) resources/views/ قوالب HTML، الجداول، النماذج، أزرار الإجراءات، وتصميمات الطباعة الورقية.
التفاعلات (JS / Vite) resources/js/pages/ & app.js مستمعات الأحداث (Click Events)، النوافذ المنبثقة، وقارئ الباركود، وبناء Vite.
محرك بايثون للطباعة scripts/printing/print_engine.py الطباعة المباشرة على طابعات الإيصالات الحرارية وطابعات الباركود عبر USB/Network.

3 المخطط الانسيابي العام لتشخيص الأعطال (Troubleshooting Flowchart)
⚠️ حدوث مشكلة أو خطأ في النظام
1. واجهة المستخدم (UI)
شكل أو زر لا يستجيب افحص Console في المتصفح بالضغط على F12.
خطأ جافاسكريبت؟ تتبع ملف الصفحة في resources/js/ أو تداخل مستمع الأحداث.
ملف Vite مفقود؟ شغّل أمر تجميع الأصول npm run build.
2. الروابط والصلاحيات
خطأ 404 Not Found تأكد من اسم الرابط ونوعه (GET/POST) في routes/web.php.
خطأ 403 Forbidden مراجعة الصلاحيات والـ Gates في AppServiceProvider.
خطأ 419 Token Expired تأكد من وجود @csrf داخل النموذج أو تجديد الجلسة.
3. العمليات (Backend)
خطأ 500 أو فشل الحفظ افتح فوراً أحدث سطر في storage/logs/laravel.log.
خطأ تحقق 422 Unprocessable فحص قواعد $request->validate في الـ Controller.
خطأ قيود الحذف (FK 1451) فحص العلاقات المرتبطة في قاعدة البيانات واستخدام حذف آمن.
4. المخزون و FIFO
اختلاف في رصيد الصنف افتح كشف حركة الصنف /products/{id}/ledger.
تتبع منطق التكلفة والوارد مراجعة دوال InventoryService (إضافة، صرف، تحويل).
فحص الجداول مباشرة جداول: stock_movements و inventory_batches.
5. محرك الطباعة
طباعة عبر المتصفح فحص ملفات Blade المخصصة للطباعة وتنسيقات CSS بحجم الصفحة.
طباعة إيصالات بايثون التأكد من تشغيل بايثون واختبار الطابعة عبر --list-printers.
قوالب الفواتير مراجعة PrintTemplateService وإعدادات الترويسة واللوجو.
4 شجرة التشخيص وحلول السيناريوهات الشائعة (Actionable Solutions)

🔴 السيناريو (أ): زر الحذف ينقل لصفحة أخرى أو لا يعمل

  • السبب 1 (تداخل نقر الصف Row-Click): وجود كود جافاسكريبت يجعل كامل صف الجدول قابلاً للنقر، فيبتلع نقرة زر الحذف.
    الحل: إضافة data-action="view" على الخلايا فقط، واستثناء عمود الإجراءات أو استدعاء e.stopPropagation().
  • السبب 2 (قيد المفتاح الأجنبي FK Constraint): الصنف مرتبط بفواتير بيع أو شراء سابقة وقاعدة البيانات تمنع حذفه (restrictOnDelete).
    الحل: إظهار رسالة تنبيه واضحة للمستخدم بعدم إمكانية الحذف لوجود حركات، أو أرشفة الصنف (Soft Delete).

🟡 السيناريو (ب): عدم استجابة الطباعة المباشرة عبر بايثون

  • السبب 1 (اسم الطابعة غير مطابق): اسم الطابعة المسجل في إعدادات النظام لا يطابق الاسم الفعلي المعرف على ويندوز.
    الحل: مطابقة الاسم بدقة عبر الأمر python print_engine.py --list-printers.
  • السبب 2 (عدم استجابة خدمة بايثون): فحص كود الخطأ الراجع من السيرفر في تبويب Network؛ إذا كان مسار بايثون غير معرف يتم ضبطه في ملف .env (PYTHON_BINARY_PATH).
